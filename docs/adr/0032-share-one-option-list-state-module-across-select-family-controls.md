# Share one option-list state module across select-family controls

Select-family controls share one internal option-list state module that owns the open state, the active option, and the keyboard contract, while each public control keeps its own selection cardinality and its own rendered interface. The behaviour was duplicated across two near-identical controls, so a keyboard fix had to be applied twice and the multi-selection control had no keyboard coverage at all; a state module makes the keyboard contract directly testable as "keys in, active option out" without rendering a component. Composition is used rather than a shared base component, per ADR-0022, because the generic parameters for single and multiple selection do not unify cleanly and the controls already inherit from the form input base.

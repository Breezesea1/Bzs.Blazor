# Name the elements tests need through the DOM contract

Bzs.Blazor names the internal elements a test or a consumer stylesheet must reach with `data-bzs-*` contract attributes rather than leaving them reachable only by their BEM class. Browser tests had been selecting a dialog backdrop, an avatar's visual, a DataGrid's detail panel, sort-precedence badge, and column-chooser option, and a button's loading icon by class name, which made a CSS rename a test break and contradicted the repo's rule that tests observe public behaviour rather than internal DOM shape. Some of those elements are deliberately hidden from assistive technology — a backdrop and a decorative icon have no accessible name by design — so an ARIA-only rule would leave them unreachable; a contract attribute states the identity explicitly and separates it from the styling hook, extending the same convention ADR-0031 established for anchored overlays. Where an element already had a public identity, the tests use it instead: expanding a DataGrid row now clicks the button named "Expand row 1", and choosing a radio option clicks its visible label.

Browser tests also build every address through the catalog's own link seam, so a route rename or a host base-path change reaches them through `DemoCatalogDestinations` instead of through eighty hand-written URLs. Test-owned routes that no visitor-facing destination covers — the per-render-mode productivity variants and the drawer lifecycle harness — are named on the same adapter, so the suite still has one place that knows where things live. Route strings themselves stay pinned by literal expectations in the adapter's own tests, by the landing page's component-group navigation cases, and by the static-markup href assertions, so a rename cannot pass silently just because both the link and the expectation moved together.

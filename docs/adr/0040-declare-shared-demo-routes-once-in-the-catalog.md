# Declare shared demo routes once in the catalog

The Demo Catalog declares every route that both demo hosts serve once, in `Bzs.Blazor.Demo.Catalog/Routes`, both hosts' routers scan the Catalog assembly through their `AdditionalAssemblies`, and the server host's `MapRazorComponents` pipeline registers the same assemblies through `AddAdditionalAssemblies` — both registrations are load-bearing, because the Router component scan drives client-side navigation while the endpoint registration drives static SSR, and a missing one makes the routes 404 on one layer only. So a shared URL is written on one wrapper instead of two near-identical ones. This replaces the previous deliberate duplication of wrapper folders between `Bzs.Blazor.Demo.Client` and `Bzs.Blazor.Demo.WebAssembly`, which existed only because the standalone WebAssembly host cannot scan the client assembly. The wrappers keep their server-facing `@rendermode` directives; on the standalone WebAssembly host the directives are inert because the whole application already runs in WebAssembly, so the visitor-reachable route surface is unchanged on both hosts. Routes that carry host-specific behavior stay host-owned: the home route passes the host-supplied `IncludesServerRenderModes` value, keeping the chrome explicitly host-parameterized per ADR-0028, the client keeps the server-only navigation-drawer lifecycle harness at `/test/navigation-drawer` and the `/productivity/auto` variant, and the server project keeps the static, server, and auto render-mode workbench pages it already owned. `DemoRouteOwnershipTests` pins the exact template set of each route-owning location and asserts that no template is declared twice across the scanned folders, because a duplicate would throw an ambiguous-route exception at startup.

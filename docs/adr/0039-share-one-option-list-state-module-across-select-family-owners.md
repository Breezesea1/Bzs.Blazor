# Share one option-list state module across select-family owners

Bzs.Blazor uses one internal Option List state module for the Select, MultiSelect, and Autocomplete option lists. This extends ADR-0032 from the two controls that share `BzsSelectOption<TValue>` to the asynchronous Autocomplete owner without merging their public option types or selection semantics. The module is generic over the owner's option type and receives explicit visible-option snapshots together with owner-supplied disabled and identity rules. It owns open state, the active option, synchronising that active option when a snapshot changes, and the shared keyboard transitions while the panel is open. Select and MultiSelect keep local search text and filtering, selection cardinality, bulk operations, and closed-panel opening behaviour. Autocomplete keeps its query, Provider Request Lifecycle, strict-text commit, selection, loading, failure, and retry behaviour. Every owner keeps its public parameters, events, rendered interface, and ARIA projection. Select and MultiSelect identify options by their already-unique values; Autocomplete adds no uniqueness requirement and clears its snapshot before a new query or retry, so each new provider result activates its first enabled suggestion. When a Select or MultiSelect snapshot changes while open, the module preserves the active option only if the same identity remains enabled, otherwise it activates the first enabled option; this replaces the former accidental index retention. Search and query state do not cross the seam, and Period Menu coordination and typeahead remain owned by the date picker's existing state module. Tests for open-state navigation, snapshot replacement, disabled options, commit requests, and close requests move to the Option List module interface, while owner tests retain only adapter mapping, public behaviour, and integration paths.

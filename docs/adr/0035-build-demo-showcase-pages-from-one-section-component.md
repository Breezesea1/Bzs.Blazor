# Build demo showcase pages from one section component

Demo Catalog pages compose their demonstrations from a shared showcase-section component rather than hand-writing the heading, description, and accessible-name markup per page. The frame was written out roughly thirty times across ten pages, each with its own CSS class for the same heading block, so a change to section typography or labelling meant visiting every page and its stylesheet; and because the frame was copied rather than shared, two pages had already drifted into rendering headings the CSS never styled. A page now passes its wrapper class, its copy, and its example, and contributes further styling through a header class it targets with `::deep`. The shared heading treatment lives in the global catalog stylesheet because a page's isolated CSS cannot reach an element a child component rendered.

Visitor-facing copy that pages had been switching with inline `IsChinese` ternaries moves into `DemoText`, so a translation lives in one place and the existing catalog canary covers it. This changes one behaviour deliberately: `DemoText` resolves the active culture the way the whole catalog does, from `CurrentUICulture`, whereas the Forms page had been reading the `?culture=` query parameter directly and therefore fell back to English when no parameter was present. That page now defaults to zh-Hans like every other, which is what ADR-0027 asks for. The layout page additionally composes its preview-beside-snippet pairing from its own small component, because that pairing is specific to that page and its snippets carry significant whitespace.

Rendered markup is otherwise unchanged apart from the heading block's class name, which no test asserted on; the snippet ids and every `data-testid` the browser tests drive are preserved.

# Own the current provider call in one module

Bzs.Blazor owns cancellation, supersession, and outcome classification for one asynchronous provider operation in a shared internal Current Provider Call module. Autocomplete and DataGrid have independently proven the same implementation: starting a call cancels the one it replaces, only the latest call may produce an accepted outcome, and completion is classified as succeeded, failed, or superseded. This satisfies ADR-0026's condition that cancellation and stale-result suppression may be shared only after duplication is proven. The module's small interface accepts an asynchronous operation and supplies its cancellation token; feature adapters translate their typed provider contracts into that operation and interpret the successful value. Each invocation owns and disposes its own cancellation source after the operation completes, while replacement, explicit cancellation, and module disposal only request cancellation. An `OperationCanceledException` is superseded only when the module token was cancelled or the invocation is no longer current; an exception raised by the current operation without module cancellation is a failure. Autocomplete keeps query rules, debounce, null-result validation, loading, retry, and presentation in its adapter and owner. DataGrid keeps request equality, queueing, retry, retained failure state, page correction, result validation, and loading in the Provider Request Lifecycle. The feature-specific provider contracts remain separate, no public interface or rendered behaviour changes, and duplicate coordinator tests are replaced by tests through the Current Provider Call interface plus focused adapter and integration coverage.

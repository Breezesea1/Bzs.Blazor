# Bzs.Blazor 0.1.12

This hardening release expands lifecycle coverage, reduces complex form-state
maintenance cost, and shortens pull-request feedback while preserving the
public component contract.

## Highlights

- Exercises real package-only Static SSR form posts for text, number, date,
  checkbox, radio, select, and repeated multi-select values, including server
  validation failures.
- Verifies form labels, tab relationships, and input focusability across the
  Auto prerender-to-interactive handoff.
- Locks dialog startup behavior so a registered static host returns
  `Unavailable` while a missing host remains an actionable configuration error.
- Extracts DateInput conversion and Gregorian calendar calculations into pure,
  focused helpers and shares proven Select/MultiSelect navigation algorithms.
- Consolidates collocated JavaScript module import, retry, diagnostics, and
  disposal while preserving typed feature wrappers and non-transient failures.
- Hardens interop cleanup races so late imports, feature disposal failures, and
  managed callback references are cleaned up deterministically.
- Adds a fast pull-request build/unit gate while retaining complete Release,
  browser, trimming, and WASM AOT gates on `main` and release tags.
- Enforces explicit NuGet package, symbols package, and AOT framework size
  budgets during release verification.

## Breaking Changes

None. Public API baselines, component parameters, events, render modes, DOM
semantics, keyboard behavior, and JavaScript operation contracts are unchanged.

## Publication

Pushing this release preparation commit to `main` starts CI. A successful CI
run triggers the GitHub Pages demo deployment. After that exact-SHA CI run
succeeds, pushing the strict `v0.1.12` tag starts the guarded NuGet workflow.

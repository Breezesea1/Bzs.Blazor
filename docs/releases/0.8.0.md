# Bzs.Blazor 0.8.0

This release hardens the wiring around the components rather than the
components themselves. The Demo Catalog's shared routes are declared once and
registered with server endpoint routing, the Linux visual-baseline font
environment becomes repository-owned instead of distribution-owned, and the
local release gate stops comparing pixels on hosts that cannot reproduce the
baselines. Public component contracts remain unchanged.

## Highlights

- A server host resolving pages through endpoint routing finds every shared
  catalog destination again: the route consolidation had moved the `@page`
  components into the catalog assembly and taught the Router components about
  it, but server-side static SSR resolves endpoints through
  `MapRazorComponents`, whose additional assemblies still listed only the
  client assembly, so every shared route 404'd on the server host.
- Shared demo routes are declared once in `Bzs.Blazor.Demo.Catalog`, and both
  hosts take the catalog assembly as an additional assembly, so the full and
  standalone hosts can no longer drift apart on a shared URL. Host-owned
  routes stay with their hosts.
- The generic `monospace` family is pinned by a repository-owned fontconfig
  installed by every workflow that captures or compares visual baselines,
  closing the one generic-family resolution that distribution defaults could
  silently change.
- `verify-release.ps1` skips the advisory pixel comparison on non-Linux hosts
  by default and warns why; the Linux CI visual jobs keep the strict default.

## Public API

No public parameter, event, provider contract, option type, template,
rendered interface, ARIA semantic, or form contract changes in this release.
Component-internal helpers moved under `Internal` folders, and folder names
still do not leak into the public namespace.

## Compatibility

This is a non-breaking release. Existing consumers can upgrade from 0.7.1
without source changes. The routing work is Demo-owned, the font pin and
release-gate change are pipeline-owned, and the supported Interactive Server,
Interactive WebAssembly, Interactive Auto, and static SSR boundaries remain
unchanged.

## Demo

The Demo Catalog now identifies 0.8.0 as the latest release and keeps the
installation command in sync with the package version. Server hosts that
register the catalog through endpoint routing serve the shared destinations
again, and browser tests lock route parity between the two hosts by naming a
destination and a culture instead of building URLs.

## Publication

Pushing the release commit to `main` starts CI and the dependent GitHub Pages
deployment. After the exact-SHA CI run succeeds, pushing the strict `v0.8.0`
tag starts the guarded NuGet workflow. Publication remains subject to the
protected `nuget-production` environment.

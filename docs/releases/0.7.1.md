# Bzs.Blazor 0.7.1

This patch release consolidates the asynchronous provider and option-list
state that had been maintained in parallel by several controls. The change is
internal: public component contracts, rendered interfaces, ARIA semantics,
form integration, and supported render modes remain unchanged.

## Highlights

- Autocomplete and DataGrid now share one internal Current Provider Call
  module for cancellation, supersession, stale-result suppression, explicit
  outcomes, and per-invocation cleanup.
- Select, MultiSelect, and Autocomplete now share one generic internal Option
  List state module. Owners submit explicit visible-option snapshots and keep
  their own query, filtering, selection, and provider policies.
- Select and MultiSelect preserve the enabled active option by identity when an
  open snapshot is reordered or replaced, and fall back to the first enabled
  option when that identity disappears or becomes disabled.
- Autocomplete starts each new provider result at its first enabled suggestion,
  clears stale suggestions before a new query or retry, and continues allowing
  duplicate suggestion values.
- Additional regression coverage locks provider races, option-list transitions,
  duplicate suggestions, MultiSelect Space policy, and owner search reset
  behavior.

## Public API

No public parameter, event, provider contract, option type, template, rendered
interface, ARIA semantic, or form contract changes in this release.

## Compatibility

This is a non-breaking patch release. Existing consumers can upgrade from
0.7.0 without source changes. The shared modules are internal implementation
details; the supported Interactive Server, Interactive WebAssembly,
Interactive Auto, and static SSR boundaries remain unchanged.

## Demo

The Demo Catalog now identifies 0.7.1 as the latest release and keeps the
installation command in sync with the package version. No new server-only
behavior or dependency is introduced in the static GitHub Pages host.

## Publication

Pushing the release commit to `main` starts CI and the dependent GitHub Pages
deployment. After the exact-SHA CI run succeeds, pushing the strict `v0.7.1`
tag starts the guarded NuGet workflow. Publication remains subject to the
protected `nuget-production` environment.

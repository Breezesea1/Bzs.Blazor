# Bzs.Blazor 0.6.0

This release finishes the anchored-overlay consolidation: every floating surface
in the library now shares one internal module, which retires the parallel state
machines and most of the component JavaScript they served. The rest of the work
is internal seams, test coverage, and completing the Demo Catalog's bilingual
copy — no theme or markup changes a consumer would see.

## Highlights

- Select, MultiSelect, and the date picker calendar now route their positioning,
  outside-interaction, Escape, and open/close synchronization through the shared
  anchored-overlay module that dialogs, drawers, menus, popovers, and tooltips
  already used. The date picker had reimplemented the module's retry contract
  with six flags and two version counters; that is gone.
- `BzsSelect.razor.js` shrinks to native required-validation focus recovery, and
  `BzsDateInput.razor.js` to the three things the shared module cannot do: read
  the browser's current date, focus the active day, and scroll the active period
  option into view. Between them the two modules lose about 390 lines.
- The select-family controls share one option-list state module, so the open
  state, search text, and active-option keyboard handling are defined once
  instead of duplicated between two controls that were about 95% identical.
- The DataGrid's provider request lifecycle — queueing, supersession, failure
  retention, page correction, and cancellation — moves behind one internal
  session, replacing two disagreeing notions of which request was current.
- The date picker's month and year period menus move into a state module with an
  injectable timeout clock, so typeahead buffer expiry is asserted rather than
  waited for.
- Every Demo Catalog page now reads its visitor-facing copy from the bilingual
  text catalog, so a Chinese visitor is no longer greeted in English after
  clicking past the landing page.

## Public API

- `CloseFromBrowserAsync` on `BzsSelect<TValue>`, `BzsMultiSelect<TValue>`, and
  `BzsDateInput<TValue>` gains an optional `bool restoreFocus = false`
  parameter, matching the surfaces already on the overlay seam.

No other public parameter or event change. Rendered markup gains `data-bzs-*`
contract attributes on the elements tests had been selecting by BEM class, and is
otherwise unchanged. Theme tokens, override hooks, and supported render modes are
unchanged.

## Internal Structure

- Adds the internal option-list state module shared by the select family, and
  generalizes the index helpers so autocomplete uses them instead of its own
  copies (ADR-0032).
- Routes every anchored surface through the overlay seam, expressing each
  surface's render-time positioning facts as DOM contract attributes the module
  queries: anchor, panel, width relation, initial focus target, nested open
  surface, and keyboard profile (ADR-0031).
- Adds the DataGrid provider request session (ADR-0033) and the date picker
  period menu state module (ADR-0034).
- Removes the dead `BzsDataGridOperations.Apply`; the test that called it now
  asserts the same stable-sort-before-paging behaviour through the production
  pipeline, across a page boundary where an unstable sort or an off-by-one page
  window would show.

## Tests

- Browser tests reach every page and element through named contracts rather than
  hand-built URLs and BEM class selectors: they name a destination and a culture
  and let the catalog's link seam supply the base path and culture-preserving
  query (ADR-0036). Elements that have no ARIA identity to use instead carry
  `data-bzs-*` contract attributes.
- One observation module now owns console capture, page errors, network traffic,
  tracing, and failure artifacts for all three ways a test acquires a page,
  including the browser matrix that previously collected no page errors.
- Two visual baselines capture an open anchored surface for the first time — a
  select panel and a calendar — so a panel that merely looks wrong is now caught
  by a gate rather than incidentally by a geometry assertion.
- Chrome copy expectations read from the text catalog instead of a transcription
  of it, with a canary pinning the visitor-facing wording for both cultures.

## Demo

- The showcase frame every demonstration repeats — a bilingual heading, an
  optional description, a live example — becomes one component instead of being
  written out about thirty times across ten pages (ADR-0035). This also fixed
  two pages that had drifted into rendering headings the CSS never styled.
- Overlays, Tabs, Layout, Feedback, Foundation, and Theme foundation now read
  their copy from the text catalog. Three specimens keep their hard-coded copy
  on purpose: the English, Simplified Chinese, and right-to-left tab groups
  demonstrate the component under a specific language and writing direction, so
  following the visitor's culture would erase what they exist to show.
- The Forms page now defaults to zh-Hans rather than falling back to English
  when no culture parameter is present, matching every other page and ADR-0027.

## Compatibility

Source-compatible for every consumer. The three `CloseFromBrowserAsync`
overloads gain an optional parameter, which is a binary-breaking signature
change for a caller that was compiled against 0.5.0 and is not recompiled;
recompiling against 0.6.0 requires no source edit. Consumers who do not call
`CloseFromBrowserAsync` are unaffected either way.

The deleted overlay logic never was a public contract — collocated component
modules are loaded by the components that own them. Theme tokens, CSS custom
properties, override hook names, component parameters, and events are unchanged.
Rendered markup gains `data-bzs-*` contract attributes, which are additive: no
class, ARIA attribute, or element structure changed, so existing CSS and
selectors keep working. Passive markup remains useful under Static SSR.

## Publication

Pushing the release commit to `main` starts CI and the dependent GitHub Pages
deployment. After the exact-SHA CI run succeeds, pushing the strict `v0.6.0`
tag starts the guarded NuGet workflow. Publication remains subject to the
protected `nuget-production` environment.

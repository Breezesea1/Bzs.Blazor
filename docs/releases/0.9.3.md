# Bzs.Blazor 0.9.3

This release closes an Autocomplete defect that surfaced during the 0.9.2
publication gate. Pressing Enter while a suggestion request was still in flight
committed the raw query against an empty option list, so the component reported a
"must match a suggestion" validation error for text the user had not finished
choosing. Enter is now ignored while suggestions are loading.

## Highlights

- `BzsAutocomplete` ignores Enter while `_loading` is true. Both entry points are
  guarded: the closed-panel path that commits the typed query directly, and the
  open-panel path that fell through to `CommitQuery()` when no option was active.
  A user who presses Enter during a slow or debounced suggestion request no
  longer sees a spurious validation error.
- Selection is untouched. Enter still commits the active suggestion when
  suggestions have loaded, and the strict-mode behaviour that rejects genuinely
  unmatched text after the list has settled is unchanged — only the in-flight
  window is different.
- The timing-sensitive unit test behind the 0.9.2 gate failure was made
  deterministic in the preceding commit. It released the provider completion and
  pressed Enter without waiting for the results to be applied and rendered; it now
  waits for the rendered option list first.

## Public API

No public API changes. The fix is confined to the internal key-down handling of
`BzsAutocomplete<TValue>`; the public API analyzer baseline is unchanged.

## Compatibility

This is a non-breaking release. Existing consumers can upgrade from 0.9.2
without source changes. The only behavioural difference is that Enter during an
in-flight suggestion request no longer produces a validation error. The
supported Interactive Server, Interactive WebAssembly, Interactive Auto, and
static SSR boundaries remain unchanged.

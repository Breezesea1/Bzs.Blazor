# Bzs.Blazor 0.1.13

This patch release fixes DateInput JavaScript initialization and cleanup races
observed during standalone WebAssembly navigation.

## Highlights

- Rejects missing or unusable DateInput roots before registering JavaScript
  state, preventing partial instances after failed initialization.
- Removes DateInput instance state before cleanup and guarantees document-level
  listener cleanup even when element cleanup fails.
- Cancels component-lifetime waits for in-flight module imports and feature
  calls without overriding Blazor's configured JavaScript invocation timeout.
- Observes abandoned import and invocation tasks, disposes late modules exactly
  once, retries cleanly after failed imports, and reports non-transient failures
  at error level while retaining debug diagnostics for transient failures.
- Treats null initialization results as uninitialized and adds deterministic
  lifecycle, logging, retry, and enhanced-navigation regression coverage.

## Breaking Changes

None. Public APIs, rendered semantics, JavaScript operation names, and supported
render modes are unchanged.

## Publication

Pushing this release preparation commit to `main` starts CI. A successful CI
run triggers the GitHub Pages demo deployment. After that exact-SHA CI run
succeeds, pushing the strict `v0.1.13` tag starts the guarded NuGet workflow.

# Bzs.Blazor 0.1.2

This patch release fixes overlay host lifecycle handling during client-side
navigation in standalone Interactive WebAssembly applications.

## Highlights

- Allows a route-owned `BzsOverlayHost` to unregister without permanently
  disposing the browser application's scoped overlay services.
- Completes pending dialog requests with `HostDisposed` while a host is being
  replaced, then accepts new requests after the replacement host activates.
- Preserves service-owned toast state when navigation replaces the overlay
  host within the same WebAssembly application scope.
- Adds component-level coverage for replacing a disposed host in the same
  dependency-injection scope.
- Adds a published standalone WebAssembly browser test that navigates between
  overlay-host routes and verifies dialogs, toasts, console output, and the
  Blazor error UI.

## Breaking Changes

None. Public component APIs, render-mode support, static SSR behavior, and the
no-third-party-runtime-dependency boundary remain unchanged.

## Publication

This version is published through the GitHub Actions workflow started by the
annotated `v0.1.2` tag. Install it with:

```text
dotnet add package Bzs.Blazor --version 0.1.2
```

Package symbols use Source Link to map sources to the
[GitHub repository](https://github.com/Breezesea1/Bzs.Blazor). Publication uses
the controlled tag-push authorization and the protected `nuget-production`
environment with NuGet.org Trusted Publishing.

# Bzs.Blazor 0.2.2

This patch consolidates the anchored overlay lifecycle behind one shared
internal session and fixes concurrency, focus restoration, and disposal
behavior across `BzsPopover`, `BzsTooltip`, `BzsMenu`, `BzsContextMenu`, and
`BzsAutocomplete<TValue>`.

## Highlights

- Deepens the anchored overlay implementation behind an internal
  `BzsAnchoredOverlaySession` that owns instance identity, desired-state
  versioning, bounded retry, close/focus intent, cancellation, and idempotent
  disposal.
- Serializes initialization and render synchronization with
  latest-state-wins semantics and a bounded immediate retry budget.
- Coalesces concurrent close requests into one controlled transition and
  preserves focus intent across asynchronous close callbacks.
- Retains the existing Razor markup, CSS, JavaScript module path, JavaScript
  export names, and public API surface.

## Fixes

- Concurrent close sources no longer invoke `OpenChanged(false)` more than
  once for a single open-state transition.
- An accepted asynchronous close no longer loses its focus restoration when
  the controlled parent replays an intermediate `Open=true` render.
- A transient JavaScript failure no longer restores focus more than once when
  the synchronization is retried.
- A rejected `BzsContextMenu` pointer invocation no longer positions a later
  programmatic open.
- `BzsMenu` and `BzsContextMenu` re-check disposal after awaiting the shared
  session.

## Compatibility

There are no breaking changes to previously published APIs. The runtime package
keeps its dependency boundary and supports Static SSR, Interactive Server,
Interactive WebAssembly, Interactive Auto, and standalone WebAssembly.

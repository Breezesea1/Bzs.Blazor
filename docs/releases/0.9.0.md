# Bzs.Blazor 0.9.0

This release hardens the wiring around the components and softens the
built-in shadow language. The overlay host keeps its toast live region
mounted before the first toast arrives, a nested theme provider warns
in development instead of silently pinning its subtree, the theme token
drift gate closes its blind spots, DataGrid resize handles announce
real pixel values, and the built-in shadow depth tokens lose visual
weight.

## Highlights

- `BzsOverlayHost` now always renders its toast region. Each toast
  already carried `role=status`/`role=alert` with `aria-live`, but the
  region itself mounted together with the first toast, which screen
  readers announce unreliably. The empty region disables pointer
  events, and the forced-colors outline appears only when it holds
  content.
- A `BzsThemeProvider` nested inside another logs a once-per-instance
  development warning. An inner provider re-pins `data-bzs-theme` for
  its subtree and freezes it against outer mode changes, which caused
  the earlier white-dialog-in-dark-mode defect. Nesting remains
  supported for intentional theme stages such as the demo's theme
  stages, which surface the expected warning in the browser console.
- The theme token drift gate asserts exact token-name parity in both
  directions between `BzsTheme.cs` and the static stylesheet, including
  the previously unchecked `--bzs-control-*` trio, and a new test
  parses `BzsThemeCssBuilder` output for the default theme and requires
  every value to match the static stylesheet, so custom-theme scopes
  can never diverge from the built-in themes.
- DataGrid resize handles advertise a pixel range anchored at the
  shared 48-pixel minimum instead of a 0–100 range with a
  column-position value, and the browser module maintains
  `aria-valuenow` and `aria-valuemax` from measured widths on every
  render, drag, and keyboard step, so the announced value finally
  moves. A unit test keeps the JavaScript minimum constant in sync with
  the server constant.
- The built-in shadow depth tokens soften: blur radii grow and
  opacities drop on the raised, inset, and overlay shadows of both
  themes while the raised and inset offsets stay put and the overlay
  offsets grow slightly, so surfaces communicate depth with less visual
  weight. `bzs.blazor.css` and `BzsTheme.cs` change in lockstep and the
  visual baselines are refreshed from the pinned CI Linux environment.

## Public API

`BzsThemeProvider` gains a public `CascadedContext` cascading parameter
(`BzsThemeContext?`) through which a provider observes the cascade it
renders into; the nested-provider development warning is built on it,
and the parameter is recorded in the public API list. No existing
parameter, event, provider contract, option type, template, rendered
interface, ARIA semantic, or form contract changes in this release.

## Compatibility

This is a non-breaking release. Existing consumers can upgrade from
0.8.0 without source changes. The toast region, nesting warning, and
drift-gate work are component-internal or diagnostic, the resize-handle
semantics correct an announced value without changing resize behavior,
and the supported Interactive Server, Interactive WebAssembly,
Interactive Auto, and static SSR boundaries remain unchanged.

## Demo

The Demo Catalog now identifies 0.9.0 as the latest release and keeps
the installation command in sync with the package version. The demo's
intentional theme stages produce the expected nested-provider warning
in the browser console.

## Publication

Pushing the release commit to `main` starts CI and the dependent GitHub
Pages deployment. After the exact-SHA CI run succeeds, pushing the
strict `v0.9.0` tag starts the guarded NuGet workflow. Publication
remains subject to the protected `nuget-production` environment.

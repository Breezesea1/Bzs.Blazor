# Bzs.Blazor 0.9.2

This release recalibrates the built-in light theme's depth language. The raised,
inset, and overlay shadows lose visual weight — blur radii grow, opacities drop,
and the offsets spread slightly — so light surfaces read as softer and further
back. Component structure, contrast, and the focus ring are untouched, and the
dark scheme keeps its current depth.

## Highlights

- The light depth tokens soften. `--bzs-shadow-raised` becomes
  `5px 7px 19px rgb(112 116 122 / 0.29), -5px -5px 14px rgb(255 255 255 / 0.72)`,
  `--bzs-shadow-inset` becomes
  `inset 2px 2px 9px rgb(112 116 122 / 0.3), inset -2px -2px 8px rgb(255 255 255 / 0.68)`,
  and `--bzs-shadow-overlay` becomes `0 17px 34px rgb(45 48 54 / 0.2)`. The
  raised and inset offsets spread by a pixel or two, the blur radii grow by a
  few pixels, and every opacity drops. `--bzs-shadow-focus` is untouched, so
  focus rings keep their current visibility.
- `bzs.blazor.css` and `BzsTheme.cs` change in lockstep, so the theme token
  drift gate and the custom-theme parity test stay green; the dark scheme's
  depth record is unchanged.
- The movement stays inside the pinned Linux visual gate's tolerance — eight
  channel levels per pixel over at most half a percent of pixels — so no
  baseline had to be recaptured. A `Refresh visual baselines` dispatch reported
  that the committed baselines already match the pinned environment.

## Public API

No public API changes. The release moves three values inside the built-in
`BzsThemes.Default` light depth record; the theme contract, the token names, and
the public-API analyzer baseline are unchanged.

## Compatibility

This is a non-breaking release. Existing consumers can upgrade from 0.9.1
without source changes. Consumers that override the depth tokens still win with
their own values; consumers that rely on the built-in light shadows see softer
surfaces. The supported Interactive Server, Interactive WebAssembly, Interactive
Auto, and static SSR boundaries remain unchanged.

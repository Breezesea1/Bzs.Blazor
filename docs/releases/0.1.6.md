# Bzs.Blazor 0.1.6

This patch release replaces the interactive native date input with a
culture-aware custom calendar while preserving a useful native date control
during static SSR.

## Highlights

- Adds a custom calendar for `DateOnly`, `DateTime`, `DateTimeOffset`, and their
  nullable forms without introducing a third-party UI dependency.
- Opens the calendar at the pointer location, follows the input during scroll,
  flips or clamps inside the viewport, and remains usable in short viewports.
- Uses the browser Popover top layer to escape transformed and paint-contained
  ancestors, with a fixed-position fallback for older browsers.
- Adds complete arrow, Home, End, PageUp, PageDown, Enter, Space, and Escape
  keyboard interactions with managed focus restoration.
- Adds localized month, weekday, accessible date, Today, Clear, and validation
  text, including consistent Gregorian dates for non-Gregorian cultures.
- Supports `Min`, `Max`, complete round-trippable `DateFormat` values, nullable
  clearing, and offset-preserving `DateTimeOffset` selection.
- Clears parsing errors when users recover through calendar selection or Clear,
  and removes `InputBase` validation state when the component is disposed.
- Expands unit, browser, accessibility, reflow, containment, and fallback
  coverage for the date picker and Demo catalog.

## Breaking Changes

None. Existing supported date value types, EditForm integration, render modes,
static SSR behavior, and the no-third-party-runtime-dependency boundary remain
intact.

## Publication

Pushing this release preparation commit to `main` starts CI. A successful CI
run triggers the GitHub Pages demo deployment. NuGet publication remains a
separate guarded action and starts only when the annotated `v0.1.6` tag is
pushed.

# Bzs.Blazor 0.3.0

This feature release expands form input behavior, provider-backed DataGrid
workflows, and modal navigation-drawer lifecycle support without breaking
previously published APIs.

## Highlights

- Extends `BzsTextInput` with `Text`, `Email`, and `Search` semantics plus
  `Change` and IME-safe `Input` update modes.
- Adds `BzsPasswordInput`, an EditForm-integrated password control with an
  optional accessible reveal action that preserves focus and caret position.
- Adds `BzsDataGrid<TItem>.RefreshAsync()` for reloading the current provider
  request while preserving latest-state-wins coordination and accepted rows.
- Adds independent DataGrid pagination and page-size visibility controls.
- Adds an opt-in current-page select-all control that preserves selections from
  other pages and respects controlled component state.
- Completes the modal lifecycle for temporary and responsive
  `BzsNavigationDrawer` presentations, including initial focus, Tab containment,
  Escape dismissal, background isolation, scroll locking, viewport changes,
  disposal, and accepted-close focus restoration.

## Public API

- Adds `BzsTextInputType`, `BzsInputUpdateMode`, `BzsPasswordInput`, and the
  curated `Eye` and `EyeOff` icons.
- Adds `RefreshAsync`, `ShowPageSizeSelector`, `ShowPagination`, `ShowSelectAll`,
  and `SelectAllText` to `BzsDataGrid<TItem>`.
- Adds `CloseOnEscape` and `InitialFocusSelector` to `BzsNavigationDrawer`.

## Reliability And Delivery

- Keeps modal drawer background isolation from disabling sibling overlay hosts.
- Covers password reveal, IME composition, DataGrid refresh and selection, and
  navigation-drawer modal behavior in real browser lifecycles.
- Verifies the new capabilities through Server, WebAssembly, Auto, standalone
  WebAssembly, package-consumer, trimming, and WebAssembly AOT gates.
- Stabilizes theme-switching visual baselines by disabling motion and waiting
  for the public theme state before capture; approved baseline images are
  unchanged.

## Compatibility

There are no breaking changes to previously published public APIs. Existing
component defaults remain unchanged, and passive markup remains useful during
Static SSR. The package continues to support Interactive Server, Interactive
WebAssembly, Interactive Auto, and standalone WebAssembly without a third-party
UI dependency.

## Publication

Pushing the release commit to `main` starts CI and the dependent GitHub Pages
deployment. After the exact-SHA CI run succeeds, pushing the strict `v0.3.0`
tag starts the guarded NuGet workflow. Publication remains subject to the
protected `nuget-production` environment.

# Bzs.Blazor 0.9.1

This release fixes a stacking defect that let an open navigation drawer cover
anchored overlay panels, and it consolidates internal duplication behind shared
modules. Anchored panels now open in the platform top layer, where no ancestor
stacking context can hide them, and the modal panel lifecycle, the
overlay-owner protocol, and the severity, level, and size lookups each live in
one internal module instead of being re-declared by every component that used
them.

## Highlights

- Anchored overlay panels opt into the browser top layer. The shared
  anchored-overlay module already contained that path — `showTopLayer()`
  returns early unless the panel matches `[popover]` — but `BzsPopover` never
  rendered the attribute, so the branch was unreachable and every anchored
  surface stayed an in-place fixed panel inside the app shell's stacking
  context. There the panel's `z-index` cannot clear the sibling navigation
  drawer, which establishes its own stacking context: at an 800x1000 viewport
  the DataGrid column filter panel rendered from x=211 to x=515 while the open
  drawer covered everything up to about x=280, and the drawer's resize handle
  took the left edge of the filter input, leaving the `Value` field and its
  Apply button partly unreachable. `BzsPopover` now renders
  `popover="manual"` on the panel, which activates the module's existing show
  and hide pairs for every consumer — DataGrid column menus, Popover, Menu,
  Select, MultiSelect, and the date picker. Browsers without a usable Popover
  API keep the previous in-place fixed fallback.
- The modal panel lifecycle has one owner. `Dialog` and `Drawer` carried
  byte-identical lifecycle state and activation logic — the open/modal/
  initial-focus diff, the pending-sync flag, and the render-time
  activate/deactivate against the overlay bridge. That bookkeeping moved into
  an internal `BzsModalPanelLifecycle` owner, so both shells keep only their
  markup, parameters, and public events, and six focused tests exercise the
  owner through its internal interface.
- The overlay-owner protocol lives in the anchored session. Eight overlay owners
  each re-declared the session's protocol: an attempt-limit constant, a lazy
  `GetOverlaySession()`, a hand-built desired-state record, a browser-close
  bridge, and a dispose block — 145 occurrences, with the attempt limit already
  drifted by a copy-paste accident. The session now owns the limit, the
  desired-state construction and validation, the browser-close policy, and
  disposal; each owner creates the session once in `OnInitialized` and
  supplies only what varies. Owners drop 159 lines.
- Severity, level, and size lookups are single-sourced. The severity mapping
  was verbatim across `Message`, `Badge`, `Toast`, and `AppBar`, the
  surface-level switch was byte-identical in `Surface` and `AppBar`, and
  three size switches covered the same small/medium/large set. Each concept now
  lives in one internal module under `Common/Internal`, with thirty focused
  tests covering every enum member and the undefined-value fallthrough.
- Agent-facing documentation gained the cumulative verification-tier guide and
  the architecture decision history.

## Public API

No public API changes. The three refactors are internal, the overlay fix
changes only the rendered panel markup, the public-API analyzer baseline is
untouched, and the two public severity enums stay separate.

## Compatibility

This is a non-breaking release. Existing consumers can upgrade from 0.9.0
without source changes. Anchored panels render in the top layer where the
browser supports the Popover API; their appearance, placement, dismissal, and
focus behavior are unchanged, and the supported Interactive Server, Interactive
WebAssembly, Interactive Auto, and static SSR boundaries remain unchanged.

## Demo

## Publication

Pushing the release commit to `main` starts CI and the dependent GitHub Pages
deployment. After the exact-SHA CI run succeeds, pushing the strict `v0.9.1`
tag starts the guarded NuGet workflow. Publication remains subject to the
protected `nuget-production` environment.
